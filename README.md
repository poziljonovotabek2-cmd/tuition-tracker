# Мини-учёт оплат учебного центра

Python + FastAPI + SQLAlchemy + PostgreSQL, Telegram-бот на HTTPX. Node.js не требуется.
Бот обращается к API по HTTP. Ученики создаются через бота или Swagger `/docs`; в боте есть поиск и история оплат.

## Запуск с нуля через Docker

Нужны Docker Engine/Desktop и Docker Compose v2. В терминале перейдите в папку проекта:

```bash
cd /home/devhouse/Documents/Codex/2026-10-27/1-api-1-2-3-get/outputs/tuition-tracker
cp .env.example .env
python3 -c "import secrets; print(secrets.token_hex(32))"
```

В файле `.env` задайте `POSTGRES_PASSWORD` и вставьте сгенерированный ключ в `API_KEY`.
В `DATABASE_URL` задайте тот же пароль базы. Создайте бота через [@BotFather](https://t.me/BotFather)
и укажите токен в `BOT_TOKEN`.

```bash
docker compose --profile bot up -d --build
```

Compose запускает PostgreSQL, API и Telegram-бота. PostgreSQL опубликован на порту `5433`,
чтобы не конфликтовать с уже установленной базой на `5432`. Внутри Docker-сети API
подключается к базе по адресу `db:5432`.

Проверить запуск и посмотреть журналы:

```bash
docker compose --profile bot ps
docker compose logs -f bot
```

Когда в журнале появится `Bot started`, отправьте боту `/start`. Документация API доступна
по адресу http://localhost:8000/docs. В pgAdmin для этой Docker-базы используйте Host `localhost`,
Port `5433`, Database `tuition`, Username `tuition` и пароль из `POSTGRES_PASSWORD`.

После изменения `.env` пересоздайте бота:

```bash
docker compose --profile bot up -d --force-recreate bot
```

Остановить сервисы, сохранив данные базы:

```bash
docker compose --profile bot down
```

Для чистой установки из архива предварительно распакуйте его и перейдите в созданную папку
`tuition-tracker`. Не публикуйте `.env` и токен бота.

После `/start` под полем ввода появляется постоянная панель кнопок (ReplyKeyboardMarkup): «Внести оплату», «Должники», «Ученики», «Добавить ученика», «Найти ученика», «Помощь».
Кнопка «Язык / Til» переключает интерфейс между русским и узбекским. Выбор действует до перезапуска бота.
Оплата: выбор ученика → ввод суммы → подтверждение. На каждом вложенном экране есть «Назад».
Списки разбиты на страницы; из карточки ученика и списка должников можно перейти к оплате.
Команды `/debt`, `/pay 12 150000.50`, `/students`, `/help`, `/id` также поддерживаются.
Любой пользователь Telegram может открыть личный чат с ботом и работать с общими данными центра.
Не используйте публичный режим для реальных ученических данных без отдельной авторизации;
пользователи могут видеть телефоны, долги, историю, создавать учеников и вносить оплаты.
Токен и `.env` не публикуйте. Запускайте только один экземпляр бота.
Используется long polling, поэтому публичный HTTPS-адрес не нужен.
Если у этого токена ранее был webhook, удалите его методом `deleteWebhook` Telegram API.

### pgAdmin и существующая PostgreSQL

pgAdmin — клиент, а данные хранит сервер PostgreSQL. Для базы из Docker зарегистрируйте
в своём pgAdmin сервер: Host `localhost`, Port `5433`, Database `tuition`, Username
`tuition`, Password — ваш `POSTGRES_PASSWORD`. Если pgAdmin сам работает в контейнере,
`localhost` указывает на него самого: используйте доступный адрес хоста либо общую Docker-сеть.

Для уже существующей PostgreSQL создайте отдельную базу `tuition` и пользователя с правами
создания таблиц в её схеме. Укажите в `.env`:

```dotenv
DATABASE_URL=postgresql+psycopg://USER:URL_ENCODED_PASSWORD@HOST:5432/tuition
```

Затем запускайте API локально по инструкции ниже. В этом случае Docker-база не нужна.
Для существующей PostgreSQL проще запустить API и бота локально: задайте её адрес в `.env`
и следуйте инструкции ниже. Если API работает в Docker, задайте `DOCKER_DATABASE_URL`
с адресом внешней базы, доступным из контейнера. Секреты передавайте через `.env`.

## Локальный запуск без Docker для Python

Нужны Python 3.11+ и работающая PostgreSQL. Если PostgreSQL нет, можно поднять только её:
`docker compose up -d db` после настройки `.env`.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
# Настройте .env как описано выше.
uvicorn app.main:app --reload
```

В другом терминале из той же папки:

```bash
source .venv/bin/activate
python -m app.bot
```

Таблицы создаются автоматически при старте API. Это начальная схема MVP;
изменение существующей схемы автоматически не мигрируется.

## API

Все операции с данными требуют заголовок `X-API-Key`. `/health` проверяет доступ к БД.

| Метод | Путь | Действие |
|---|---|---|
| POST | `/students` | Создать ученика |
| GET | `/students?offset=0&limit=100&q=Азиза` | Список учеников; q — необязательный поиск по имени/телефону |
| GET | `/students/{id}` | Получить ученика |
| PATCH | `/students/{id}` | Изменить указанные поля |
| DELETE | `/students/{id}` | Удалить ученика **вместе с его оплатами** |
| POST | `/payments` | Добавить оплату |
| GET | `/students/{id}/payments` | Оплаты ученика, новые сначала; offset/limit |
| GET | `/debtors?month=2026-10` | Должники за месяц |

GET-запросы списка учеников и должников кэшируются в памяти API до 30 секунд.
Создание, изменение и удаление ученика, а также новая оплата сразу очищают кэш.
Кэш локален для процесса API; при внешнем изменении БД или нескольких worker-процессах
обновление произойдёт после истечения TTL.

Примеры (замените ключ):

```bash
export API_KEY='your-key-from-env'
curl -X POST http://localhost:8000/students \
  -H "X-API-Key: $API_KEY" -H 'Content-Type: application/json' \
  -d '{"name":"Азиза","phone":"+998901234567","group":"Python-1","monthly_fee":"500000.00"}'

curl -X POST http://localhost:8000/payments \
  -H "X-API-Key: $API_KEY" -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: payment-example-1' \
  -d '{"student_id":1,"amount":"200000.00","date":"2026-10-27"}'

curl 'http://localhost:8000/debtors?month=2026-10' -H "X-API-Key: $API_KEY"
```

Ответ для примера:

```json
[{"student_id":1,"name":"Азиза","phone":"+998901234567","group":"Python-1","monthly_fee":"500000.00","paid":"200000.00","debt":"300000.00"}]
```

Деньги хранятся как `NUMERIC(14,2)`, рассчитываются через `Decimal` и возвращаются строками.
Используйте одну валюту для всего центра. Оплата строго положительная, тариф — от нуля.
Максимум два знака после точки. Дата оплаты — календарная дата `YYYY-MM-DD`.
`Idempotency-Key` необязателен для API; бот автоматически передаёт уникальный ключ оплаты или подтверждённого создания ученика.
Повтор с тем же ключом и телом возвращает прежнюю оплату, с другим телом — HTTP 409.
Два самостоятельных сообщения `/pay` считаются двумя разными оплатами.

### Правила расчёта

- Учитываются все оплаты с первого числа месяца включительно до первого числа следующего,
  исключая следующий месяц. Неплативший ученик должен полную месячную сумму.
- Полная оплата и переплата исключают ученика из должников. Переплаты не переносятся.
- Для `/debt` текущий месяц определяется через `TIMEZONE`, по умолчанию `Asia/Tashkent`.
  Для `/pay` используется дата отправки сообщения в этом часовом поясе.
- MVP использует **текущий тариф и текущий список учеников для любого запрошенного месяца**.
  Изменение тарифа меняет прошлые отчёты; даты зачисления и помесячные начисления пока не ведутся.
- Удаление ученика необратимо удаляет его оплаты. Это явная операция API;
  команды удаления в боте нет.

## Проверки

```bash
pip install -r requirements.txt
pytest -q
```

По умолчанию используются отдельные SQLite-БД в памяти; PostgreSQL для этих тестов не требуется.
Проверяются CRUD, платежи, границы месяца и года, високосный день, дробные суммы,
нулевой тариф, частичная/полная оплата, переплата, валидация, авторизация и идемпотентность,
а также команды, кнопки, переходы назад, подтверждение, права доступа и повторы после сетевых ошибок с HTTP-заглушкой.

Чтобы прогнать API-тесты на настоящем PostgreSQL, создайте **отдельную пустую тестовую базу**:

```bash
TEST_DATABASE_URL='postgresql+psycopg://USER:PASSWORD@localhost:5432/tuition_test' pytest -q
```

**Тесты создают и удаляют таблицы в указанной тестовой базе. Не используйте рабочую базу.**
Реальный Telegram в автоматических тестах не вызывается.

Остановка Docker: `docker compose --profile bot down`. Данные сохраняются в volume `pgdata`.
Команда `docker compose down -v` удаляет данные. Для резервной копии:

```bash
docker compose exec -T db pg_dump -U tuition tuition > backup.sql
```

### Обновление кнопочного интерфейса

```bash
docker compose --profile bot up -d --build api bot
```

После обновления отправьте `/start`. Незавершённые диалоги хранятся в памяти и при
перезапуске сбрасываются; старое подтверждение предложит начать заново. Сохранённые
оплаты остаются в PostgreSQL. Ключ оплаты привязан к сообщению с суммой: повторное
нажатие подтверждения и повтор после сетевой ошибки не создают вторую оплату.

### Тестовые ученики

Добавить пять демонстрационных учеников (имена с пометкой «тест», группы DEMO):

```bash
docker compose exec -T api python - < app/seed.py
```

Или при локальном запуске: `python -m app.seed`.
Повторный запуск пропускает уже существующие телефоны и не меняет учеников или оплаты.
Демонстрационные оплаты не создаются. Тестовые ученики будут отображаться в должниках.
Чтобы убрать демоданные, удалите учеников из групп DEMO через API.

### Создание, поиск и история в боте

- «Добавить ученика»: имя → телефон → группа → месячный тариф → подтверждение.
  До подтверждения ничего не записывается. Тариф допускает 0, телефон — 7–15 цифр.
  Форматирование телефона пробелами/скобками удаляется. «Назад» позволяет исправить данные.
- «Найти ученика»: часть имени (без учёта регистра в PostgreSQL) или телефона.
  В телефонном поиске игнорируются пробелы, скобки, дефисы и «+».
  Результаты разбиты на страницы. Возврат из карточки сохраняет поисковый запрос.
- «История оплат» в карточке: дата, сумма и номер оплаты, новые сначала.
  Есть переключение страниц и возврат в ту же карточку.
- Создание ученика через API поддерживает необязательный `Idempotency-Key`.
  Нормализованное тело запроса связывается с ключом в отдельной таблице
  `student_creation_requests`; она создаётся автоматически при старте новой версии API.
  Повтор с тем же ключом не создаёт второго ученика даже после сетевого сбоя.
  Изменение тела с тем же ключом возвращает 409. Повторная отдельная анкета считается
  новым учеником; одинаковые телефоны допустимы, например у детей одного родителя.
